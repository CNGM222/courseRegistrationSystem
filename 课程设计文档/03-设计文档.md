# 高校课程注册系统设计文档

| 文档信息 | 内容 |
| --- | --- |
| 文档编号 | CRS-SDD-001 |
| 版本与日期 | V1.0，2026-09-09 |
| 需求基线 | CRS-SRS-001 V1.0 |
| 实现方案 | Vue 3 + Spring Boot 3 + MySQL 8，B/S 前后端分离 |

## 1. 设计目标与约束

系统围绕学生、教师和教务员三个角色实现八个核心用例。设计首先保证学生最多四门有效课程、教学班最多十人、备选不提前占位、关闭注册的一致性，以及成绩和课表的对象级权限。

课程目录保留为外部只读权威来源，新业务存入 MySQL，用户通过现代浏览器中的 Vue 页面访问系统。真实旧数据库与财务接口未提供时，使用独立模拟适配器验证契约，不宣称已经完成真实对接。

采用需求文档 AD-01 至 AD-12 的业务解释，特别是首次正式提交 4+2、补位后一次最终取消、不循环补位、关闭时生成最终费用、字母成绩 A/B/C/D/F/I。任何解释变化须同步事务算法、数据模型和测试。

## 2. 总体架构

![系统总体架构](assets/architecture.png)

### 2.1 部署与逻辑分层

浏览器访问 Nginx 提供的 Vue 静态资源，并通过同源 /api 路径调用 Spring Boot。后端以模块化单体实现，使用 MySQL 8 的 InnoDB 事务与行锁。实际部署可以从单实例开始，按测量结果扩展多个后端实例；登录会话使用 Spring Session JDBC 共享。

| 层次 | 职责 | 约束 |
| --- | --- | --- |
| Vue 展示层 | 页面路由、输入校验、工作方案、状态与错误展示 | 不自行决定容量、角色权限、成绩归属或费用 |
| Controller 接口层 | 身份上下文、请求校验、DTO 转换、统一响应 | 不直接拼接 SQL，不包含完整业务算法 |
| Application Service | 用例编排、事务边界、锁获取、审计与错误映射 | 业务写入必须经过服务层 |
| Domain Policy | 先修、冲突、容量、备选和费用规则 | 使用明确输入输出，便于独立验证 |
| Mapper 持久层 | SQL、索引访问、锁查询、条件更新 | 限制查询列，所有参数绑定 |
| Integration 适配层 | 目录读取、快照构建、财务消息投递 | 外部网络调用不放在选课或关闭数据库事务内 |

### 2.3 关键技术决策

| 决策 | 选择及理由 |
| --- | --- |
| 认证方式 | 服务端 Session + HttpOnly Cookie，便于撤销账号权限并减少浏览器持有凭据 |
| 数据访问 | MyBatis，便于明确控制 FOR SHARE、FOR UPDATE、条件更新与批量查询 |
| 并发依据 | 数据库事务及锁，不使用仅在单 JVM 内有效的 synchronized 作为容量保证 |
| 消息可靠性 | 事务消息表 Outbox + 定时投递，减少课设基础设施数量并解决本地提交后漏发 |
| 目录性能 | 有版本的 MySQL 发布快照，页面与选课读取本地；远程同步独立执行 |
| 前端组件 | Element Plus，表格、表单、对话框和分页保持一致；Pinia 仅存 UI 状态与用户摘要 |

## 3. 领域模型与状态

### 3.1 领域关系

![核心实体关系](assets/entity-relationships.png)

Course 是课程，CourseOffering 是学期教学班；一个课程可对应多个教学班。Student 在一个 Semester 中拥有一个 Schedule。ScheduleChoice 保存某个版本的主选与备选意向，Enrollment 才表示实际占位。Grade 依赖真实 Enrollment。Invoice 保存关闭注册时的最终课表及费用，OutboxEvent 负责将该快照可靠发送到财务系统。

教师资格 ProfessorQualification 与实际任课 CourseOffering.professorId 分开：有资格不代表已经选择授课，已经授课也不能越过时间冲突校验。

### 3.2 状态机

![注册与课表状态](assets/state-transitions.png)

| 对象 | 状态 | 允许变化 |
| --- | --- | --- |
| 学期 | PREPARATION、OPEN、CLOSED | 初始化导入后 PREPARATION → OPEN；关闭事务成功 OPEN → CLOSED；关闭计算中的 CLOSING 仅为事务内逻辑阶段，不单独持久提交 |
| 教学班 | OPEN、CLOSED、CANCELLED | 发布后 OPEN；关闭成功时变为 CLOSED 或 CANCELLED；无重新开放接口 |
| 课表 | DRAFT、REGISTERED、WITHDRAWN、FINALIZED、EXPIRED | 新草稿 DRAFT；正式提交 REGISTERED；删除 WITHDRAWN；关闭时有提交历史者 FINALIZED，只有草稿者 EXPIRED |
| 注册记录 | ENROLLED、DROPPED、CANCELLED | 提交或补位为 ENROLLED；退课为 DROPPED；关闭取消为 CANCELLED；开放期重新选回可从 DROPPED 转 ENROLLED |
| 财务消息 | PENDING、IN_FLIGHT、RETRY、DELIVERED | 待发 → 抢占发送 → 已确认；失败 → 重试；租约到期的发送中消息可重新抢占 |

课表处于 REGISTERED 时仍可保存新草稿，状态保持 REGISTERED。是否存在未提交修改由 draft_revision 与 submitted_revision 比较判断，不能用单一“草稿”状态覆盖已获得名额的正式课表。

删除课表清空当前草稿与提交版本指针、撤销有效注册，并置 WITHDRAWN；保留首次提交时间和历史版本。重新编辑可以建立新草稿，首次提交次数策略以 first_submitted_at 是否为空判断，不能通过删除课表重置历史。

### 3.3 时间模型

数据库业务时间使用 UTC，接口返回 ISO 8601 时间，前端按 Asia/Shanghai 显示。学期教学日期和星期属于本地校历。注册修改时段采用半开区间：registration_start <= now < add_drop_end；registration_end 是常规选课结束时刻，registration_end 至 add_drop_end 为加退课阶段。

需满足 registration_start < registration_end <= add_drop_end。教务关闭默认要求 now >= add_drop_end，提前关闭不作为本期功能。名单与成绩以教学学期结束日期判断，成绩录入还要求注册已经 CLOSED。

## 4. 数据库设计

### 4.1 通用规范

MySQL 8.0.16 或更高版本、InnoDB、utf8mb4。主键用 BIGINT，API 中所有 ID 以十进制字符串输出，避免 JavaScript 大整数精度问题。外部事件 ID 用 UUID 字符串。金额采用 DECIMAL(10,2)，币种采用 CHAR(3)，本期一个学期仅一种币种。

所有核心外键采用 RESTRICT，不级联删除成绩、注册或计费数据。可维护实体具有 created_at、updated_at；可并发编辑的对象具有 version BIGINT。逻辑删除使用 deleted_at，敏感字段的加密密钥与 HMAC 密钥置于环境或密钥配置中，不存入数据库或 Git。

下列为关键字段字典，PK 为主键，FK 为外键，UK 为唯一约束。字符串长度为建议上限，日期与状态须同时进行接口校验。MySQL CHECK 只负责单行范围，跨行数量和对象归属由事务保证。

### 4.2 身份与人员表

#### account：账号

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id | BIGINT | PK |
| username | VARCHAR(64) | NOT NULL，UK，采用统一大小写规则 |
| password_hash | VARCHAR(255) | NOT NULL，BCrypt 摘要 |
| role | VARCHAR(16) | STUDENT / PROFESSOR / REGISTRAR，演示账号单角色 |
| enabled | BOOLEAN | 是否允许登录 |
| failed_attempts、locked_until | INT、DATETIME(3) | 登录失败限制；锁定可自动到期 |
| version、created_at、updated_at | BIGINT、DATETIME(3) | 版本与审计时间 |

#### student：学生

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、account_id | BIGINT | id 为 PK；account_id 为 FK、UK |
| name、status | VARCHAR(100)、VARCHAR(20) | 姓名；ACTIVE / INACTIVE / GRADUATED |
| birth_date、graduation_date | DATE | 出生日期必填；毕业日期可空 |
| ssn_ciphertext | VARBINARY(512) | 社会安全号码加密内容；只用合成数据演示 |
| ssn_fingerprint | BINARY(32) | 标准化号码的 HMAC-SHA256，UK；用于本表查重 |
| deleted_at、version | DATETIME(3)、BIGINT | 逻辑删除与并发版本 |

#### professor：教师

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、account_id | BIGINT | id 为 PK；account_id 为 FK、UK |
| name、birth_date | VARCHAR(100)、DATE | 姓名、出生日期 |
| status、department | VARCHAR(20)、VARCHAR(100) | ACTIVE / INACTIVE；院系 |
| ssn_ciphertext、ssn_fingerprint | VARBINARY(512)、BINARY(32) | 同学生表；fingerprint 本表 UK |
| deleted_at、version | DATETIME(3)、BIGINT | 逻辑删除与版本 |

账号角色必须与对应人员表匹配，由创建事务校验。社会安全号码的本表唯一性只用于防止同类人员重复建档，不据此推断跨角色为不同自然人。教务员账号通过初始化脚本创建，不提供公众注册入口。

### 4.3 学期与目录表

#### semester：学期与注册控制

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、code、name | BIGINT、VARCHAR(32)、VARCHAR(100) | PK；code UK |
| start_date、end_date | DATE | 教学起止日期 |
| registration_start、registration_end、add_drop_end | DATETIME(3) | 选课和加退课时段 |
| status | VARCHAR(16) | PREPARATION / OPEN / CLOSED |
| active_snapshot_id | BIGINT | FK → catalog_snapshot，可在准备阶段为空 |
| currency | CHAR(3) | 演示默认 CNY；必须与教学班费用一致 |
| closed_at、version | DATETIME(3)、BIGINT | 关闭时间、乐观版本 |

该行同时作为数据库注册门锁。初始化顺序为学期空快照 → 创建目录快照与内容 → 验证并设置 active_snapshot_id → 开放注册，不依赖循环外键同时插入。

#### catalog_snapshot：课程目录快照

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、semester_id | BIGINT | PK；FK → semester |
| source_version、content_hash | VARCHAR(128)、CHAR(64) | 外部版本和内容摘要 |
| status | VARCHAR(16) | STAGING / PUBLISHED / REJECTED |
| fetched_at、verified_at、published_at | DATETIME(3) | 获取、最近完整校验、发布时间 |
| source_kind、last_error | VARCHAR(32)、VARCHAR(500) | LEGACY / MOCK；脱敏错误摘要 |

#### course：版本化课程镜像

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、snapshot_id | BIGINT | PK；FK → catalog_snapshot |
| legacy_course_id、code | VARCHAR(64) | 外部稳定 ID、课程代码；UK(snapshot_id, legacy_course_id) |
| name、department | VARCHAR(200)、VARCHAR(100) | 课程名称与院系 |
| credits | DECIMAL(4,1) | 正学分，演示范围在导入校验中约束 |

#### course_prerequisite：先修关系

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| course_id、prerequisite_course_id | BIGINT | 联合 PK；分别 FK → course |
| 校验规则 | 服务校验 | 不可自依赖；必须属于同一快照；导入时检测先修环 |

课程按快照版本隔离。检查历史先修时按 legacy_course_id 跨快照匹配，不能比较不同学期内部 course.id；通过任一已结束学期的 A 至 D 成绩即满足该门直接先修要求。

#### course_offering：教学班目录与本地状态

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、semester_id、snapshot_id、course_id | BIGINT | PK 与相关 FK；课程及学期必须匹配快照 |
| legacy_offering_id、section_code | VARCHAR(64)、VARCHAR(32) | UK(snapshot_id, legacy_offering_id)；教学班编号 |
| professor_id | BIGINT | 可空，FK → professor，本地实际授课教师 |
| min_students、max_students | SMALLINT | 固定 3、10；CHECK(min_students=3 AND max_students=10) |
| enrolled_count | SMALLINT | 默认 0；CHECK 0 <= enrolled_count <= max_students |
| status、cancel_reason | VARCHAR(16)、VARCHAR(32) | OPEN / CLOSED / CANCELLED；NO_PROFESSOR / BELOW_MINIMUM |
| tuition、currency | DECIMAL(10,2)、CHAR(3) | 非负费用，币种与学期一致，注册期冻结 |
| version | BIGINT | 人数、任课或状态变化均递增 |

目录源中的教师姓名若存在，仅作为 source_teacher_name 等参考信息导入；实际教师由本地 professor_id 表示。同步程序不得覆盖 professor_id、enrolled_count、status 或 version 等本地业务字段。课程、费用和上课安排在学期开放后整体冻结，源出现变化时报告差异，转入人工评审，不自动改动当前选课规则。

#### offering_meeting：教学周次与时间

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、offering_id | BIGINT | PK；FK → course_offering |
| week_no、weekday | SMALLINT | 周次 1 至 30，星期 1 至 7 |
| start_period、end_period_exclusive | SMALLINT | [开始节次, 结束节次)，范围 1 至 13 且开始小于结束 |
| room | VARCHAR(100) | 教室或上课地点 |
| 唯一索引 | 复合 UK | offering_id + week_no + weekday + start_period + end_period_exclusive |

将每个教学班的实际上课周展开成记录，单周、双周通过存在的 week_no 表示。一条 1 至 2 节课程保存为 [1,3)，3 至 4 节为 [3,5)，两者不冲突。周次定义以该学期校历为准，不能把不同学期的相同 week_no 判作冲突。

#### professor_qualification：授课资格

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| professor_id、course_id | BIGINT | 联合 PK，分别 FK → professor、course |
| source_ref、imported_at | VARCHAR(128)、DATETIME(3) | 资格来源及导入时间；课程对应当前快照 |

资格在注册开始前导入，注册期内不提供业务页面修改。缺少资格映射时不展示为可选授课课程，不能默认所有教师可教所有课程。

### 4.4 课表与成绩表

#### schedule：课表聚合根

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、student_id、semester_id | BIGINT | PK；FK；UK(student_id, semester_id) |
| status | VARCHAR(16) | DRAFT / REGISTERED / WITHDRAWN / FINALIZED / EXPIRED |
| draft_revision、submitted_revision | BIGINT | 可空，分别指向当前工作方案和已正式提交方案 |
| latest_revision | BIGINT | 从 0 起递增，分配不可变意向版本 |
| first_submitted_at | DATETIME(3) | 首次成功正式提交时间，之后不重置 |
| version | BIGINT | 每次保存、提交、删除或关闭均递增 |

#### schedule_choice：不可变版本意向

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、schedule_id、revision | BIGINT | PK；FK → schedule；版本由 schedule 分配 |
| offering_id | BIGINT | FK → course_offering |
| kind、priority | VARCHAR(16)、SMALLINT | PRIMARY 优先级 1 至 4；ALTERNATE 优先级 1 至 2 |
| 唯一约束一 | 复合 UK | (schedule_id, revision, offering_id) |
| 唯一约束二 | 复合 UK | (schedule_id, revision, kind, priority) |

版本中的空方案可以没有 choice 行，指针仍合法。revision 是应用分配的逻辑版本，不能直接对它建立指向明细行的外键；在课表行锁事务内生成版本、写完整明细并更新指针。不同教学班若对应同一 legacy_course_id，则由服务拒绝重复。

#### enrollment：实际注册

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、schedule_id、offering_id | BIGINT | PK；FK；UK(schedule_id, offering_id) |
| state | VARCHAR(16) | ENROLLED / DROPPED / CANCELLED |
| source | VARCHAR(16) | PRIMARY / ALTERNATE |
| reason | VARCHAR(32) | USER_DROP / SCHEDULE_DELETE / NO_PROFESSOR / BELOW_MINIMUM 等 |
| enrolled_at、updated_at | DATETIME(3) | 生效与变更时间 |

人数只统计 ENROLLED。快照版本、学期和学生所属必须由服务验证一致。保留 DROPPED/CANCELLED 记录用于历史追踪；开放期选回同班复用该记录，避免同班重复占位。

#### grade：当前成绩

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| enrollment_id | BIGINT | PK、FK → enrollment，一条注册最多一条当前成绩 |
| value | CHAR(1) | NOT NULL，CHECK 值在 A/B/C/D/F/I 中 |
| recorded_by | BIGINT | FK → professor，必须为该班实际授课教师 |
| recorded_at、updated_at、version | DATETIME(3)、DATETIME(3)、BIGINT | 时间与并发版本 |

无 grade 行代表尚未录入；I 是已录入的“不完整”成绩。当前有效名单以 CLOSED 教学班的 ENROLLED 注册为准。修订成绩更新 grade 并记录受权限保护的审计事件；公共访问日志不得输出成绩列表。

### 4.5 关闭、计费与审计表

#### registration_close：关闭结果

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、semester_id | BIGINT | PK；FK；semester_id UK，学期只关闭成功一次 |
| run_id | CHAR(36) | UK，关闭关联 ID |
| registrar_account_id | BIGINT | FK → account |
| closed_at、summary | DATETIME(3)、JSON | 成功时间，课程取消、补位、学生和账单数量等摘要 |

该记录与业务关闭一起提交；失败时没有成功结果行。关闭失败的运维日志可存在，但不能被界面误认作完成记录。

#### billing_invoice：不可变计费快照

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、schedule_id、student_id、semester_id | BIGINT | PK；FK；schedule_id UK；UK(student_id, semester_id) |
| close_id | BIGINT | FK → registration_close |
| total_amount、currency | DECIMAL(10,2)、CHAR(3) | 关闭时总额和币种 |
| created_at | DATETIME(3) | 形成快照的时间 |

#### billing_invoice_item：费用与最终课表明细

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| id、invoice_id、offering_id | BIGINT | PK；FK；UK(invoice_id, offering_id) |
| course_code、course_name、section_code | VARCHAR(64)、VARCHAR(200)、VARCHAR(32) | 关闭时展示快照，后续不依赖源名称变化 |
| professor_name、meeting_snapshot | VARCHAR(100)、JSON | 当时授课教师及时间，供最终课表展示 |
| amount | DECIMAL(10,2) | 本教学班应缴金额，非负 |

#### outbox_event：财务投递消息

| 字段 | 类型 | 约束与说明 |
| --- | --- | --- |
| event_id | CHAR(36) | PK；整个重试生命周期不变 |

## 5. 核心业务详细设计

### 5.1 草稿与正式注册分离

保存草稿只新建一组不可变 ScheduleChoice，更新 draft_revision 和 version，不变更 Enrollment、submitted_revision 或教学班人数。学生界面同时显示“工作方案”和“当前有效课表”。

提交时将选定草稿中的主选与当前有效注册求差集。新增主选占位，移除主选退课；已存在的主选保持原记录。提交成功后 submitted_revision 指向本次版本，备选也随该版本成为关闭注册使用的有效备选。尚未提交的新草稿不影响关闭时的备选选择。

例如：已正式提交 A/B/C/D，备选 E/F；后来草稿改为 A/B/C/G，备选 H/I，但未提交。此时 D 的名额仍属于学生，G 尚未占位，关闭时仍使用 E/F。

### 5.2 容量与事务策略

所有注册相关写操作按统一顺序获取锁：学期行 → 对应学生或教师档案行 → 课表行 → 按 ID 升序的教学班行 → 注册明细和其他从属数据。同类批量对象按 ID 升序获取；跨角色人员维护需遵守同一顺序。修改学期相关人员状态也必须经过学期门锁。

普通选课和授课事务先执行学期 SELECT ... FOR SHARE，确认 OPEN 和修改时段。多个普通事务可同时持有共享锁；关闭注册使用同一行的排他锁，因此不会在选课尚未完成时取得关闭权。

学生档案行和课表行使用 FOR UPDATE，串行化同一学生的方案更新。新增课表也先锁学生，避免首次创建竞争。教师授课修改锁教师档案，防止两个请求同时给同一教师分配冲突课程。

事务采用 READ COMMITTED，加显式锁保证业务对象一致性。网络调用、页面等待和轮询均不得持有数据库锁。锁等待设置较短超时，死锁或竞争返回可重试冲突；重试必须重新读取版本和状态。

### 5.3 学生提交算法

![课表提交时序](assets/submit-sequence.png)

1. 从会话取得学生 ID，不接受请求体指定操作者。校验 DTO 的主选、备选和版本格式。
2. 开启事务，按顺序锁学期、学生和课表，重新检查账号与学生状态、OPEN、时间范围、If-Match 版本。
3. 读取 draft_revision 对应完整方案；若是首次正式提交则要求 4+2，之后允许最多 4+2；所有选项必须属于当前学期的发布快照且课程不重复。
4. 获取当前 ENROLLED 集合与目标主选，求保留、新增、移除集合；按 ID 升序锁它们涉及的全部教学班。
5. 校验目标主选的先修、时间冲突、状态；每个新增班重新检查容量。备选此时仅校验所属学期、目录有效性、去重和顺序，容量、先修及与最终课表冲突在补位时复核。
6. 对移除集合设置 DROPPED 并减少人数，对新增集合原子增加人数并写入或恢复 ENROLLED。若某一步失败，抛出业务异常回滚全部变化。
7. 更新 submitted_revision、first_submitted_at、status 和 version，记录审计，提交事务。
8. 返回新版本、当前有效课表和已提交备选；不生成财务消息。

容量更新的关键 SQL 示意如下，参数均绑定；应用必须检查受影响行数恰好为 1：

```sql
UPDATE course_offering
SET enrolled_count = enrolled_count + 1,
    version = version + 1
WHERE id = :offering_id
  AND status = 'OPEN'
  AND enrolled_count < max_students;
```

退课只对原状态 ENROLLED 的记录执行一次减计数，且要求 enrolled_count > 0。明细状态更新、计数更新、方案指针和版本全部属于同一事务。使用 MyBatis 时参数占位需转为其标准参数绑定语法；上述为设计伪 SQL。

提交前的预检只读、不能预留名额。前端编辑时每 5 秒轮询当前方案涉及的教学班人数，页面不可见时暂停，重新聚焦时刷新；点击提交先预检展示变化，最终提交仍以数据库校验为准。轮询是容量提醒设计，不宣称实时推送。

### 5.4 先修与时间冲突

PrerequisitePolicy 接收目标课程的直接先修 legacy_course_id 集合，查询学生已结束学期的有效注册与成绩，构造 A/B/C/D 的通过课程集合。先修集合必须全部包含在通过集合中；F、I、无成绩、当前学期尚未结束的课程均不算通过。

ConflictPolicy 比较同一学期的时间片。当 week_no、weekday 相同，并且 left.start < right.end 且 right.start < left.end 时冲突。按全部目标主选互相比较；教师选择按目标完整授课集合比较；备选补位按当时已保留的有效课程比较。教室冲突与自动排课不在本期范围。

### 5.5 教师授课修改

请求提交教师希望最终保留的教学班列表。服务在学期共享门锁和教师档案行锁下，读取旧集合，按教学班 ID 升序锁新旧并集。新增班必须属于当前快照、资格匹配、未被其他教师占有且仍 OPEN；取消项必须确实属于本人。

校验完整目标集合没有时间冲突后，再统一更新 professor_id，递增教学班版本并记录审计。发现任何错误则整体回滚，不先保存“取消旧班”造成部分丢失。教师档案 version 作为本次授课方案并发版本，由 GET 返回并由 If-Match 提交，成功后递增。

### 5.6 关闭注册与备选补位

关闭在单个本地数据库事务内完成。课程规模较大时先基于锁定的一致数据构造内存工作集，在工作集中计算结果，再批量落库。不得为了缩短事务把多个学生分别提交，否则会破坏失败时业务状态保持不变的事务要求。

1. 尝试对目标 semester 行执行 SELECT ... FOR UPDATE NOWAIT。若有在途注册共享锁则立即返回 REGISTRATION_BUSY；不更改任何状态。若已 CLOSED，返回原关闭结果。
2. 验证关闭时点和教务身份。取得排他锁后新选课请求会等待或超时；取得锁后必须重新检查状态，不能凭先前读取的 OPEN 继续写。
3. 一次性加载有效注册、已提交版本的备选、教师、时间、先修成绩和费用。对人数计数进行核对，若与 ENROLLED 条数不一致则回滚并报告数据异常。
4. 先取消无教师教学班，将其所有有效注册从工作集移除。已有教师但不足三人的教学班暂时保留，等待补位后的最终复核。
5. 仅对有 first_submitted_at 的学生按首次提交时间、学生 ID 排序；使用 submitted_revision 的备选，不读取未提交草稿。WITHDRAWN 学生无提交指针，按零课表处理，不恢复其旧备选。
6. 对每位有效课程少于四门的学生，按备选 1、2 依次尝试。候选必须仍 OPEN、有教师、有余位、先修通过，与当前有效课程不重复且不冲突。成功则增加注册与人数；跳过原因记录在关闭摘要中。
7. 补位全部结束后，对仍有教师但人数不足三人的班执行取消，移除对应有效注册。其他班变为 CLOSED。此后不执行第三轮补位。
8. 根据最终 ENROLLED 集合生成不可变账单及明细。有提交历史但最终无课程者生成零金额账单；从未提交的草稿不生成账单，课表置 EXPIRED。
9. 写入 registration_close、各学生最终状态和 outbox_event，学期置 CLOSED，审计与上述数据一起提交。
10. 提交成功后，由独立投递器发送消息。财务未确认时页面显示“注册已关闭，财务通知待发送”。

算法不变量：任意时刻有效人数不超过 10；每名学生有效课程不超过 4；最终 ENROLLED 必须指向 CLOSED 且有教师、人数至少 3 的班；账单明细必须等于最终有效课表。取消导致空位是需求 AD-06 已明确允许的结果。

补位示例：班 X 有教师和 2 名学生；学生 S 因另一门无教师课程被取消而只有 3 门有效课程，第一备选为 X，先修和时间均合法。S 加入后 X 达到 3 人并保留。若另一班 Y 始终只有 2 人，它在最终复核时取消；原本四门中包含 Y 的学生可能最终只剩三门。

异常处理：使用 Spring 事务超时和数据库超时约束操作时间，团队建议关闭事务预算 90 秒，实际须压测校准；任一业务或数据库异常都使本地关闭全部回滚。远程财务重试永远不在此事务内执行。

### 5.7 可靠财务通知

OutboxDispatcher 定时扫描到期 PENDING/RETRY 消息和租约已过期的 IN_FLIGHT 消息，在短事务内使用 FOR UPDATE SKIP LOCKED 抢占一小批，设置 claim_token 与 locked_until 后立即提交；网络发送在事务外进行。

默认连接超时 2 秒、读取超时 5 秒、租约 30 秒，批量大小应保证每条消息都能在租约内开始处理；优先单条抢占或并发受限发送，不能顺序领取大批后等到租约过期。成功或失败更新须匹配 event_id 和 claim_token，过期工作线程不能覆盖新租约结果。

重试间隔建议 30 秒、1 分钟、2 分钟、4 分钟，随后上限 30 分钟并加入少量随机抖动。超过阈值生成运维提示，但不删除消息、不永久停止重试。接收端永久校验错误保留原消息并以低频重试，修复协议或数据问题须形成审计。

同一事件的 event_id 和业务键 student_id + semester_id 在所有重试中保持不变。财务接收端在自己的事务中去重、保存账单并确认；若已处理相同业务键，返回相同确认而不新建账单。

此方案提供“至少一次投递 + 接收端幂等”。网络请求本身可能重复；当财务接收成功但本地未保存确认时再次发送，必须由对方去重。真实财务接口不支持幂等时，不能宣称已解决重复账单，需在真实对接时补充协议。

### 5.8 目录同步与降级

CatalogPort 定义 fetchCatalog(semesterCode, deadline)，返回完整版本、课程、先修和教学安排。适配器分别实现 LegacySqlCatalogAdapter 与 MockCatalogAdapter，使用只读数据库账号或模拟服务，禁止 UPDATE/INSERT/DELETE 旧目录。

默认每 5 分钟尝试检查源，远程访问总预算 8 秒，为上层 10 秒截止留出处理余量。查询页始终使用本地发布快照。准备期按 STAGING 导入，检查引用完整、先修无环、时间合法、费用齐全，再原子发布；失败不破坏已发布版本。

注册期不自动改变已发布内容。若源内容摘要一致，则更新 verified_at；若源内容变化，则记录差异并等待评审，不能覆盖已选课程规则。默认有效快照要求最近完整校验在 24 小时内；超出时效或没有快照时，目录查询与依赖目录的新增提交返回 CATALOG_UNAVAILABLE。该时效为可配置设计约定。

本人现有课表、历史成绩及不依赖新目录的整表删除可以使用本地业务数据。关闭注册使用已经冻结的学期快照，不在关闭时重新连接旧系统。导入不完整、超时、源变更和快照过期分别记录状态，便于区分故障。

### 5.9 成绩与人员维护

成绩更新先由服务端查询教学班实际 professor_id，再验证每条 enrollment 属于该教学班、state 为 ENROLLED、学期已结束且 CLOSED。每个成绩携带 expectedVersion，未录入用 0；批量按 enrollment_id 升序加锁，并通过注册记录行锁串行化首次插入。出现任一非法值或版本冲突时整批回滚。

学生成绩查询不提供 studentId 参数，学生 ID 由当前会话推导；只读本人已结束学期数据。教师只通过本班名单视图看到该班所需成绩，不获得学生完整历史成绩访问能力。

师生维护采用字段白名单与 If-Match；停用、删除前按学期门锁和档案行锁检查当前有效注册或授课关联。存在关联时拒绝停用或删除，避免绕过学生退课及教师取消授课流程。个人档案仅逻辑删除，关联账号同时禁用并失效会话；历史仍可按原 ID 追踪。

## 6. REST 接口设计

### 6.1 通用契约

统一前缀 /api/v1，JSON 使用 camelCase。ID 以字符串传输，日期为 YYYY-MM-DD，时间带 UTC 偏移。成功响应为 data、requestId；分页增加 page、pageSize、total，page 从 1 开始，pageSize 默认 20、最大 100。

失败响应包含 code、message、details、requestId，details 描述字段、教学班及冲突原因，不包含堆栈、SQL 或敏感标识。HTTP 401 表示未登录，403 表示角色或对象无权，404 表示可见范围内对象不存在，409 表示容量或业务竞争，412 表示版本过期，422 表示字段或规则不符，428 表示缺少必要版本，503 表示外部依赖无可用数据。

写操作使用 Cookie 会话及 CSRF 请求头。编辑接口读取 ETag，提交 If-Match: "7" 等版本；服务端必须在取得对象锁后再比较。首次创建由唯一约束和档案锁保护，成功返回新版本。提交超时后客户端先查询当前版本及有效课表，不盲目重发；重复的旧版本提交返回 412 而不是再次占位。

成绩请求示例：未包含的学生不更新，空值不用于清除已有成绩。

### 6.5 教务接口

| 方法与路径 | 输入 | 输出或约束 |

## 7. 前端设计

### 7.1 页面与路由

| 页面 | 路由示意 | 主要组件与操作 |
| --- | --- | --- |
| 登录 | /login | 账号、密码、登录错误、提交状态 |
| 学生选课 | /student/registration | 学期筛选、课程表格、主选区、备选排序、草稿及提交 |
| 我的有效课表 | /student/schedule | 周课表和列表切换、注册状态、取消原因、草稿差异 |
| 我的成绩 | /student/report-card | 已结束学期、成绩表、未录入与无数据状态 |
| 教师授课 | /professor/teaching | 有资格教学班、已选集合、冲突提示 |
| 教师名单与成绩 | /professor/offerings/:id/grades | 学生名单、字母选择、修改状态、批量保存 |
| 学生维护 | /registrar/students | 搜索、分页、增改弹窗、删除确认 |
| 教师维护 | /registrar/professors | 搜索、分页、增改弹窗、删除确认 |
| 注册管理 | /registrar/registration | 时段与状态、关闭确认、关闭结果、通知状态 |

路由守卫只用于导航体验；所有接口仍执行后端授权。登录过期保留可恢复的非敏感工作方案，不把成绩、社会安全号码或长期凭据写入 localStorage。切换账号必须清理 Pinia 缓存与未提交的身份相关数据。

### 7.2 学生选课页交互

桌面采用课程列表与方案编辑并列布局；手机使用“课程目录 / 选课方案 / 有效课表”标签切换。主选以 4 个固定槽位呈现，备选以 2 个有序槽位呈现，避免动态文案造成位置跳动。表格显示课程、教师、时间、人数、先修和操作。

“保存草稿”始终只保存意向；“提交选课”先展示预检结果及将新增、保留、退掉的课程，再确认提交。已注册课程和未提交方案使用明确状态标识。人数满员、关闭、冲突和先修不足均提供具体对象，不只弹出通用“失败”。

当服务器返回 412 时提示方案已变化并重新读取，保留本地差异供比较；409 满员时更新相应班人数并允许修改或另存草稿。请求期间禁用同一提交按钮只是防误触，服务端仍负责并发和重复请求保护。

### 7.3 教师与教务页交互

成绩单元格使用下拉列表 A/B/C/D/F/I，初始未录入显示为空；未修改行不进入更新请求。保存错误定位到行；离开有未保存修改的页面时确认。

关闭注册页面展示目标学期、当前时段、不可逆的注册关闭结果及财务异步状态；确认对话框明确课程可能因无教师或不足三人而取消。成功关闭后只保留结果查询。师生删除先显示姓名和 ID，再由服务端检查关联，失败时展示原因。

## 8. 安全设计

### 8.1 认证与会话

使用 Spring Security 验证 BCrypt 密码，登录成功轮换 Session ID，防止会话固定。JDBC 会话支持多实例共享；账号停用后清除相关会话，并在受保护写服务中重新检查人员状态。

部署 Cookie 使用 HttpOnly、Secure、SameSite=Lax，建议空闲超时 30 分钟；本机 HTTP 开发环境的 Secure 例外只允许出现在 local profile。修改请求要求 CSRF 令牌，包括登录和退出流程。Nginx 同源部署，开发环境通过 Vite proxy，避免允许任意跨域携带 Cookie。

登录失败限制建议为连续 5 次失败锁定 15 分钟，按账号配合来源限流，参数可调整；提示不泄露账号是否存在。日志只记录请求 ID 与结果，不记录密码。

### 8.2 授权与数据保护

先进行角色鉴权，再查询资源并检查 student_id 或 professor_id 归属。对班级名单、成绩修改、课表增删及详情接口均采用相同边界，不能只保护列表页。

成绩响应设置 Cache-Control: no-store，避免浏览器和代理持久缓存；字段最小化，不把完整学生资料传给教师名单页。社会安全号码列表默认掩码，详细编辑仅教务可见；合成数据仍沿用生产级字段保护设计。

采用 Bean Validation 和业务白名单限制请求规模、字符串长度、成绩枚举和查询条件；MyBatis 全部参数绑定，排序字段使用枚举映射。前端默认转义，不将姓名、课程名或错误消息作为原始 HTML 渲染。数据库用户按业务读写、迁移管理、目录只读拆分权限。

### 8.3 审计

师生维护、授课变更、课表提交与删除、成绩修订、关闭注册和消息状态变化记录操作者、对象、时间与请求 ID。成绩内容仅在受限业务表中保存，公共日志不打印 DTO 全量；需要核验修改时结合 grade.version 和审计记录。

## 9. 性能、可靠性与部署

### 9.1 性能方案

避免目录远程 N+1 查询和每个学生逐次查询先修。目录分页按索引筛选，名单和课表批量 JOIN；关闭注册批量加载相关数据后计算，按主键批量写入。名单和计费使用固定快照，历史查询不依赖旧系统在线。

500 本地用户与 2000 总用户是并发会话目标，不是数据库连接数。可用四个应用实例各承接约 500 用户进行拓扑验证，但这只是部署方案，不能据此认定已经达标。连接池初始建议每实例 20 至 30 个连接，再根据数据库 CPU、等待和锁竞争调整。

压测报告记录查询、登录、草稿、提交、退课、授课和成绩等操作比例、思考时间、峰值并发、TPS、P50/P80/P95、错误率和锁等待。关闭注册另设包含在途事务、成功关闭及之后拒绝写入的场景，并计入业务性能说明。

性能合格需结合成功率与响应时间判断；快速返回 409、503 或空数据不能用于证明成功业务吞吐量满足要求。项目环境不足以验证 2000 用户时，应写明未验证并报告已测规模。

### 9.2 可用性与恢复

应用提供健康检查，分别显示基础存活、数据库就绪和集成状态。财务不可达是异步投递降级，不使已关闭结果丢失；目录无可用快照时会影响核心选课，应计入相应服务不可用。

建议每日全量备份并开启 binlog，备份与数据库实例分开保存；RPO 24 小时、RTO 2 小时作为课设演练目标，实际采用 binlog 时可进一步降低 RPO。恢复到隔离实例后核对人数、有效注册、成绩和未送达消息，再决定切换，不能仅检查备份文件存在。

若恢复后 Outbox 重新投递，财务仍须按业务键去重。恢复不能伪造未确认消息为已送达。敏感备份受访问控制，演示环境只使用合成数据。

### 10.2 核心不变量检查

```sql
-- 应返回零行：教学班人数与有效注册不一致。
SELECT o.id, o.enrolled_count,
       SUM(CASE WHEN e.state = 'ENROLLED' THEN 1 ELSE 0 END) AS actual_count
FROM course_offering o
LEFT JOIN enrollment e ON e.offering_id = o.id
GROUP BY o.id, o.enrolled_count
HAVING enrolled_count <> actual_count;

-- 应返回零行：学生有效注册超过四门。
SELECT schedule_id, COUNT(*) AS active_count
FROM enrollment
WHERE state = 'ENROLLED'
GROUP BY schedule_id
HAVING COUNT(*) > 4;
```

另检查 CLOSED 学期所有 ENROLLED 对应教学班均为 CLOSED、有教师且人数 3 至 10；所有账单总額等于明细金额之和、明细集合等于最终课表；同一学生学期最多一份账单；DELIVERED 消息必须具有接收确认记录。

## 11. 实施顺序与评审清单

实现顺序建议：身份及迁移 → 人员与目录 → 草稿与正式注册 → 教师授课 → 关闭与财务 → 成绩与验收。容量锁、学期门锁、版本指针和 Outbox 应先做小规模原型验证，再扩展页面功能。

小组评审须实际核对以下事项，并记录结论：

1. 确认八个核心用例完整，核对 AD-01 至 AD-12 的业务约定与实现是否一致。
2. 以具体数据演算保存草稿、提交失败、并发最后一个名额、2 人补至 3 人以及最终取消后不足四门的结果。
3. 核对所有事务锁顺序，确认关闭、授课变更及人员停用不会绕开学期门锁。
4. 核对目录快照与本地业务字段边界，确认源同步不会覆盖教师、人数、费用或历史课程。
5. 核对真实财务是否支持幂等，明确模拟与真实对接验证的区别。
6. 核对 D 的先修通过政策、资格导入、费用来源、快照时效和关闭时点。
7. 将本设计与小组实际实现逐项比较，修订差异后再形成正式提交版。
