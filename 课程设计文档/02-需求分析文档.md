## 1. 引言

### 1.1 目的

本文定义课程注册系统的业务范围、角色权限、功能、业务规则、非功能指标、异常行为和验收标准，作为后续设计、开发与测试的共同基线。本文描述系统应当提供的能力；数据库表、锁策略及具体 API 见设计文档。

### 1.2 标识约定

FR 表示功能需求，BR 表示业务规则，NFR 表示非功能需求，UC 表示用例，AD 表示业务与实现约定，AC 表示验收场景。业务约定在小组评审时统一确认，变更后同步设计和验收标准。

## 2. 业务背景与范围

学校需要替换原有课程注册应用，使学生和教师通过校园网络操作。旧课程目录保留在 DEC VAX 上的 Ingres 数据库中，学校已有 SQL 访问通道；新系统只能读取课程信息，不能更新旧目录。

学生按学期选择教学班，教师选择有资格教授的教学班，教务员维护学生与教师信息。注册关闭时确定最终有效课程、处理备选补位和人数不足取消，再通知财务系统计费。学期结束后，教师录入成绩，学生查询本人成绩单。

### 2.1 系统边界

| 范围 | 内容 |
| --- | --- |
| 系统内 | 登录权限、目录查询、师生信息、授课关系、课表、注册记录、成绩、关闭注册、财务通知状态 |
| 只读外部来源 | 课程基本信息、学分、所属院系、先修关系、教学班目录及教学时间 |
| 外部财务系统 | 接收最终课表及费用，形成账单并发送给学生 |
| 系统外流程 | 课程目录维护、真实支付、关闭后换教师、重开注册、退款和人工调账 |

MySQL 存储本系统业务数据与旧目录的本地只读快照。目录的权威来源仍是旧系统；学生注册和教师授课选择产生的本地业务状态不回写旧目录。

### 2.2 用户与外部参与者

| 参与者 | 目标 | 权限边界 |
| --- | --- | --- |
| 学生 Student | 选课、维护本人课表、查看本人成绩 | 只能操作自己的课表与成绩视图；不能维护学生基础信息或录入成绩 |
| 教师 Professor | 选择授课、查看本班名单、录入与修订成绩 | 只能管理自己教授的教学班；不能修改其他教师的授课或成绩 |
| 教务员 Registrar | 维护学生和教师信息、关闭注册 | 可管理师生基础数据及注册流程；无直接录入成绩权限 |
| 课程目录系统 | 提供课程及教学班信息 | 本系统只有读取权限 |
| 财务系统 Billing System | 接收最终计费信息并出账 | 独立系统；本系统不模拟真实收款 |

### 2.3 术语表

| 术语 | 定义 |
| --- | --- |
| 课程 Course | 抽象课程，如“软件工程”，具有课程代码、名称、学分和先修要求 |
| 教学班 Course Offering | 某门课程在某学期的具体开课实例，具有上课时间、教师和人数限制 |
| 课程目录 Course Catalog | 课程与当期开课信息的权威集合；本系统通过只读适配访问 |
| 课表 Schedule | 某学生某学期的主选、备选意向及当前有效注册结果 |
| 主选 Primary | 学生希望正式注册的教学班，常规初次提交选四门 |
| 备选 Alternate | 主选无法保留时用于补位的有序选择，共两门；不提前占用名额 |
| 名单 Roster | 某教学班中正式注册的学生集合，不包括草稿和未启用备选 |
| 成绩 Grade | A、B、C、D、F 或 I；未录入与 I 是不同状态 |
| 成绩单 Report Card | 学生某一已结束学期的课程及成绩，允许存在尚未录入项 |
| 先修课 Prerequisite | 选修某门课程前应已完成并通过的课程 |
| Transcript | 学生历次修读课程的历史成绩记录；与发送财务的计费课表分别管理，不向财务发送完整成绩历史 |

## 3. 业务与实现约定

以下约定明确系统的业务边界与实现条件。小组修改其中任一项时，须同步设计和验收标准。

| 编号 | 事项 | 本系统约定 |
| --- | --- | --- |
| AD-01 | 用户界面与运行环境 | 使用现代浏览器中的 Vue 界面，采用 B/S 架构 |
| AD-02 | 新业务数据库与旧目录集成 | MySQL 用于新业务和目录快照；真实旧系统缺失时使用独立模拟源及只读适配器 |
| AD-03 | 主选、备选与加退课数量 | 首次正式提交必须恰好 4 主选、2 备选；草稿允许 0 至 4 主选、0 至 2 备选；首次提交后的加退课允许上述范围，最终有效课程可少于 4 门 |
| AD-04 | 主选与备选的占位时机 | 主选提交成功后占位；备选只记录顺序，关闭注册补位成功时才占位，不能注册成六门课程 |
| AD-05 | 注册关闭与在途事务 | 存在尚未完成的选课或授课变更事务时不能关闭；有人浏览、在线或保存浏览器表单不阻止关闭。关闭失败保持原状态，教务员稍后重试 |
| AD-06 | 关闭注册处理顺序 | 无教师教学班先取消；有教师但暂不足 3 人的班保留到补位后复核。补位结束后一次性取消仍不足 3 人的班，不追加第三轮补位，最终课表允许不足 4 门 |
| AD-07 | 学费计算与财务通知时机 | 学生保存或提交时不出账；关闭成功后按最终课表发送一次逻辑账单，传输允许重试 |
| AD-08 | 成绩取值与可见性 | 保存 A/B/C/D/F/I 或未录入状态；默认 A 至 D 为先修通过、F 与 I 不通过；已结束学期开放录入并立即对本人可见，无额外发布审批 |
| AD-09 | 师生敏感信息与删除策略 | 保留 socialSecurityNumber 语义，仅使用合成数据；删除实现为停用及逻辑删除以保护历史，存在当前注册或授课关联时拒绝删除 |
| AD-10 | 先修、重复课程与时间冲突 | 按历史已结束学期的通过成绩检查所有直接先修课；同一方案内同门课程的不同教学班不能重复；冲突按相同周次、星期与重叠节次判断 |
| AD-11 | 学费计算规则 | 演示采用教学班固定费用；费用来自目录扩展或外部配置导入，使用精确小数及明确币种；不开设学分计费、奖学金或折扣 |
| AD-12 | 资格导入与目录快照管理 | 资格由演示导入或外部资格清单提供；目录适配器使用有时效的发布快照，注册期内冻结课程规则、时间与费用；无可用快照时结束依赖目录的操作 |

AD-06 的具体补位规则：先移除无教师教学班造成的占位；每位学生按现有有效注册数计算空位，从第一备选开始尝试。已有教师但少于 3 人的主选在最终复核前仍占一个课表位置，所以最终取消后可能留下空位。本期不进行循环补位。

教师资格数据来源、D 是否算通过、收费标准及备选竞争顺序均应由团队评审。本文默认按学生首次提交时间、学生 ID 排序补位，以保证结果确定且可重复验收。

## 4. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 每个学生每学期最多一个课表；主选最多 4 门，备选最多 2 门，首次正式提交为 4+2 |
| BR-02 | 备选按优先级 1、2 保存，不占教学班名额、不进入正式名单、不计费 |
| BR-03 | 每个教学班人数上限 10；关闭注册最终人数少于 3 时取消 |
| BR-04 | 无教师授课的教学班在关闭注册时取消，并从学生有效课表移除 |
| BR-05 | 正式注册和备选转正均检查先修、开放状态、容量、重复课程与时间冲突 |
| BR-06 | 学生只能在注册及加退课开放时段内提交、修改或删除课表；关闭后拒绝写入 |
| BR-07 | 草稿不获得名额；已有正式课表另存草稿不立即改变正式注册，必须提交成功才生效 |
| BR-08 | 多门课程作为一次方案提交，任何主选失败则本次所有新增、删除、人数和课表状态不变 |
| BR-09 | 教师只能选择有资格的教学班；每班由一位教师授课；教师授课时间不得冲突 |
| BR-10 | 关闭注册后教师不能改变授课选择；关闭后的教师变更属于系统外流程 |
| BR-11 | 仅授课教师可录入和修改本班成绩，合法值为 A/B/C/D/F/I，允许暂不录入 |
| BR-12 | 学生仅查看自己的已结束学期成绩；教务员维护基础信息不附带成绩编辑权 |
| BR-13 | 只有教务员可增加、修改和删除学生及教师基础信息，ID 由系统唯一生成 |
| BR-14 | 本系统对旧课程目录只读，授课和注册结果只存入本地业务库 |
| BR-15 | 关闭注册按最终有效课程生成费用；取消班、未启用备选、草稿和已退课程不收费 |
| BR-16 | 财务不可用时持续安排重试，不能丢弃通知；重复发送不能产生重复账单 |
| BR-17 | 课程容量变化必须在处理正式提交前展示给学生，并在最终提交时重新验证 |
| BR-18 | 关闭处理失败时业务状态不变；关闭成功后所有课程停止注册，结果可查询 |

## 6. 用例模型与详细规约

![系统参与者与用例关系](assets/use-cases.png)

八个核心用例是 UC-01 至 UC-08；目录查询、名单查询和财务通知作为其支撑行为。所有写用例失败时均保持原有业务数据不变，另行记录的失败审计不属于业务变更。

### 6.1 UC-01 登录

参与者：学生、教师、教务员。关联 FR-01。

前置条件：用户尚未登录，账号已由初始化或教务维护建立。

基本流程：

1. 用户输入登录名和密码。
2. 系统校验账号状态和密码。
3. 系统建立会话并读取服务端角色。
4. 用户进入对应工作页面。

异常流程：登录名或密码错误时统一提示“账号或密码错误”；停用或被锁定账号不能登录；网络错误保留登录页面并允许重试，不回显密码。

后置条件：成功后获得受控会话；失败时保持未登录。退出后原会话失效，后续受保护请求要求重新登录。

### 6.2 UC-02 注册课程

参与者：学生；协作系统：课程目录。关联 FR-02、FR-03。

前置条件：学生已登录且状态有效；注册未关闭，当前时间处于允许修改课表的时段；需要目录的操作具有可用目录快照。

新建与提交流程：

1. 系统展示当前学期可选教学班及容量、先修和时间。
2. 学生选择四门主选及按顺序排列的两门备选。
3. 系统在编辑时更新人数，在提交前预检并列出冲突项。
4. 学生确认提交。
5. 系统重新校验时段、版本、主选数量、先修、容量、课程重复及时间冲突。
6. 系统一次性注册全部主选，记录备选，并保存课表；返回有效课程及版本。

保存草稿：在选择过程中可暂存未完成方案；尚未注册项显示为“已选择”。若原先存在有效注册，草稿与有效课表分别展示，保存草稿不会提前退课或获得新名额。

更新：显示有效课表和待提交方案；学生增删主选或调整备选；提交成功后同时应用退课与新选，失败则旧课表及名额不变。初次提交后的加退课允许少于四门。

删除：学生查看课表并确认删除；系统撤销本人所有有效注册、释放名额并撤销草稿与备选，返回空课表。取消确认不产生变更；课表不存在时返回明确提示。

异常流程：满员、未满足先修、时间冲突、重复课程或版本过期时返回具体课程及原因；学生可以调整、另存草稿或取消本次操作。目录不可用时结束目录查询及依赖目录的提交；注册关闭时拒绝写操作；网络超时后重新查询课表确认结果，不能假设失败并重复占位。

后置条件：成功产生唯一、容量合法的课表；失败保持原有效课表。备选仍未正式注册。

### 6.3 UC-03 选择授课课程

参与者：教师；协作系统：课程目录。关联 FR-04。

前置条件：教师已登录且状态有效；注册开放；目录可用。

基本流程：

1. 系统显示教师有资格教授的教学班以及本人已选班。
2. 教师勾选新增班或取消本人已有班。
3. 系统检查资格、其他教师占用、同一周次的授课时间冲突和数据版本。
4. 系统在同一事务中应用完整选择，返回更新后的授课列表。

异常流程：无可选班时显示空状态；冲突时指明教学班和冲突时间；被他人抢先选择时提示已被选择；取消或失败不先删除原授课关系；注册关闭后禁止更改。

后置条件：所有成功变更均属于当前教师，且该教师授课不冲突。关闭后的换教师在系统外处理。

### 6.4 UC-04 提交成绩

参与者：教师。关联 FR-05、FR-06。

前置条件：教师已登录；所选学期已结束；教师确实教授该教学班；学生属于该班最终有效名单。

基本流程：

1. 系统列出上一已结束学期中该教师教授的班。
2. 教师选择教学班，系统显示学生名单及已有成绩。
3. 教师对需要更新的学生录入 A、B、C、D、F 或 I。
4. 教师提交；系统校验归属、成绩值和版本后保存本次更新，记录审计。
5. 教师可以之后继续录入遗漏成绩，也可修订已有成绩。

留空语义：首次未录入的学生保持“未录入”；本次请求省略某个学生表示不修改其已有成绩。已录入成绩不因空表单或遗漏字段被清空；明确清空已有成绩不作为本期功能。

异常流程：无授课记录或名单为空时显示空状态；非法成绩、非本班学生、非本人教学班或版本冲突时拒绝本批次修改并指出原因。

后置条件：本批次成绩全部更新或全部不变；其他教师及其他班成绩不受影响。

### 6.5 UC-05 查看成绩单

参与者：学生。关联 FR-07。

前置条件：学生已登录；请求本人已结束学期的成绩。

基本流程：系统依据会话定位学生，显示学期、课程、教学班、教师和字母成绩；学生可切换其他已结束学期（辅助查询约定）或离开页面。

异常流程：没有课程或尚无成绩时展示明确状态；未录入不能显示为 F、I 或 0。通过修改 URL、请求参数或接口直接访问他人成绩均被拒绝。

后置条件：不修改成绩或其他业务状态。浏览器及中间代理不得持久缓存成绩响应。

### 6.6 UC-06 维护学生信息

参与者：教务员。关联 FR-08。

前置条件：教务员已登录。

新增流程：输入姓名、出生日期、社会安全号码、状态、毕业日期；系统验证格式与唯一性，生成唯一学生 ID，创建关联账号并返回 ID。演示账号初始密码通过受控方式提供，不在日志中输出。

修改流程：输入学生 ID；系统显示信息；教务员编辑允许字段并保存。ID 不可修改；毕业日期允许在读时为空，已填写时不得早于出生日期。

删除流程：输入 ID 并确认；系统检查当前注册关联，无关联时停用账号并逻辑删除资料；存在当前有效注册时说明关联原因并拒绝，以避免隐式退课。历史成绩和账单仍保留。

异常流程：不存在、重复号码、日期错误、版本冲突或取消删除均不改变原记录。学生本人不能调用这些维护接口。

### 6.7 UC-07 维护教师信息

参与者：教务员。关联 FR-09。

前置条件：教务员已登录。

基本流程：新增时输入姓名、出生日期、社会安全号码、状态、院系，系统生成唯一教师 ID；修改时按 ID 检索后提交字段变更；删除时显示信息并确认后进行关联检查、账号停用和逻辑删除。

异常流程：不存在、号码重复、日期错误或版本冲突时拒绝；有当前学期授课任务时拒绝删除和停用，需由教师在开放期取消选择；历史任课记录与成绩不物理删除；取消删除无变更。

后置条件：成功时仅指定教师资料发生变更；失败保持原状态。

### 6.8 UC-08 关闭注册

参与者：教务员；协作系统：财务系统。关联 FR-10、FR-11、FR-12。

前置条件：教务员已登录；目标学期尚未关闭；注册已到允许结束的时点；不存在正在执行的学生课表或教师授课变更事务。时点校验属于防止误操作的设计约定，演示时使用预置开放及到期学期。

基本流程：

1. 教务员查看关闭确认信息并发起关闭。
2. 系统检查在途变更。存在则提示“有注册变更正在处理，请稍后重试”，立即结束且状态不变。
3. 系统取消无教师教学班，移除其有效注册；其他班保留待后续复核。
4. 对每位尚不足四门有效课程的学生，按备选优先级尝试补位，重复检查先修、冲突、教师与容量。
5. 所有补位结束后，最终人数不足三人的教学班取消，从对应有效课表移除；其余教学班停止注册并冻结名单。
6. 系统生成每个具有正式提交历史的学生的最终课表和费用快照，并持久保存财务待发通知。
7. 系统一次性提交关闭结果。教务员可以查询取消原因、最终名单与通知状态。
8. 系统向财务发送最终结果，财务接收后出账并向学生发送账单。

异常流程：本地关闭计算或数据库提交失败时全部回滚；财务不可用不撤销已成功关闭的学期，而是持续安排重试并显示“通知待发送”；重复关闭返回已关闭结果，不重新计算或创建新账单。

后置条件：注册关闭、最终有效班均有教师且人数在 3 至 10 之间、学生有效课程不超过四门；财务通知已持久记录，实际送达状态独立可查。只有草稿且从未提交的学生不产生账单；有提交历史但最终课程为零的学生发送零金额结果，以明确本学期无应缴费用（设计约定）。

## 8. 外部接口需求

### 8.1 课程目录接口

提供按学期获取课程、教学班、先修和时间数据的能力。必须使用只读账号，支持超时及失败返回，不允许在注册事务内反复远程查表。新系统应利用本地快照满足旧目录访问时延要求。

当源不可达但存在符合时效要求的完整快照时，使用该快照并展示更新时间；没有可用快照时明确报告目录暂不可用，结束依赖目录的操作，不返回伪造空目录。该缓存解释见 AD-12。

教师任课资格与收费数据通过受控导入或模拟源扩展提供，字段与来源记录在设计文档中。

### 8.2 财务接口

每份通知包含唯一事件 ID、学生 ID、学期、最终教学班列表、每班金额、总金额和币种。不得包含密码、社会安全号码或完整历史成绩。接收端以业务唯一键去重，返回确认信息。

连接失败、超时、接收端暂时错误均进入重试。格式或业务校验错误须保留消息并提示教务处理，仍按较低频率重试；不得达到次数后静默删除。真实性能和幂等协议需在真实财务对接时另行验证。

### 8.3 用户界面

界面语言为中文。学生界面包含目录、方案编辑、有效课表和成绩；教师界面包含授课选择、班级名单和成绩录入；教务界面包含师生维护、注册关闭及通知状态。操作须有加载、空数据、错误、成功和未保存变更状态。

## 9. 非功能需求

### 9.1 性能、安全与验证方式

| 编号 | 要求 | 验证口径 |
| --- | --- | --- |
| NFR-01 | 多用户并行工作；中心数据库支持 2000 同时用户，本地服务器支持 500 同时用户 | 2000 总会话负载及每实例 500 用户场景分别验证；记录硬件、实例数、操作比例、思考时间、吞吐量和错误率；不等同于 2000 TPS 或数据库连接 |
| NFR-02 | 访问旧课程目录时延不超过 10 秒 | 分别测试冷启动、有快照、源超时场景；在 10 秒内返回有效结果或明确失败；单靠快速失败不能证明成功查询性能达标 |
| NFR-03 | 80% 的全部业务事务在 2 分钟内完成 | 固定业务混合负载，统计端到端 P80 不超过 120 秒，同时报告错误率；纳入关闭注册等业务事务的单独耗时，不能只统计快读接口 |
| NFR-04 | 7×24 小时可用，停机不超过 10% | 以约定观测窗口统计可用性不低于 90%，核心依赖失败造成核心功能不可用计入；课程短期测试只能作为观测证据 |
| NFR-05 | 学生不能改他人课表；教师不能改他人授课；只有教师能录成绩；只有教务员能改学生信息 | 对每个受保护接口进行未登录、跨角色和同角色越权测试 |

在上述指标之外，拟设的优化目标为一般查询 P95 不超过 2 秒、正常选课提交 P95 不超过 3 秒；这两项为团队工程目标，不替代 NFR-01 至 NFR-04，也不代表已测得结果。
