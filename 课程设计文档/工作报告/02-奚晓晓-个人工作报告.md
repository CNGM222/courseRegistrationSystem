## 三、各阶段主要工作

### 1. 前端结构与角色工作区

我采用 Vue 3、TypeScript、Vite、Element Plus、Pinia 和 Vue Router 组织前端，建立登录、会话恢复、角色路由和公共布局。学生默认进入选课页，教师进入授课选择，教务员进入注册管理；桌面侧栏与移动导航对应同一权限和页面结构。课程目录提供关键词、院系筛选、分页和详情，展示先修要求、周次时间、费用及目录校验时间。

前端仅请求真实 `/api/v1`，连接失败会显示明确错误，不使用本地假数据代替服务响应。对于无数据、无权限、网络失败和目录不可用，我保持不同反馈，防止把接口故障显示成正常空列表。

### 2. 学生流程与状态恢复

我围绕四主选两备选完成方案编辑、备选排序、草稿保存、独立预检和确认提交，并将当前课表、历史课表和成绩单分别呈现。名额显示每五秒刷新，标签页隐藏时暂停，恢复焦点后更新；轮询只更新展示，最终名额由后端提交校验决定。

我特别关注版本冲突与会话过期。课表修改携带当前版本，冲突后提示读取最新结果；过期时只在当前标签页 Pinia 内存保留未提交方案，重新登录同一账号后提示恢复。主动退出、切换账号或正常离开编辑页清除草稿，刷新标签页会失去未保存内容。会话、成绩、个人资料和草稿均不写入 localStorage 或 sessionStorage。

### 3. 教师与教务操作界面

教师页面涵盖授课选择、本人当前和历史名单及成绩录入。当前学期名单只读，成绩保存依据学期结束及关闭条件控制；成绩未录入时版本为 null，已有版本 0 按实际版本提交，避免把合法版本误判为不存在。

教务页面支持师生增改删、初始密码设置及密码重置，并将字段错误定位到对应输入项。敏感标识只显示掩码，编辑留空保持原值。注册管理将修改截止、立即截止与最终关闭分开，关闭前确认，结果不明时先查询。最终名单只呈现学生 ID、姓名和主选或备选来源。财务状态支持筛选、分页、十秒刷新和恢复焦点刷新，并显示最近更新时间。

### 4. 接口契约与外部集成

我参与统一 DTO 和 TypeScript 类型，约定 ID 为字符串、金额为精确十进制字符串，区分 401、403、409、412、422 和 503 等响应。HTTP 封装负责 Cookie、CSRF、超时和请求关联信息；写请求断线不能据此判定失败，提示先核对结果再决定重试，不自动重放业务写操作。

目录集成采用 mock 与 legacy 适配边界，远程读取放在事务外，导入和发布使用短事务。准备期允许发布，开放后的变化暂存，不覆盖已有选课引用。财务集成使用冻结事件、稳定幂等标识和 Outbox 重试机制，并配套本地合成接收端。上述集成已形成源码和联调条件，真实学校目录、真实财务系统仍需独立对接验证。

### 5. 运行配置与交付整理

我整理前端安装、类型检查、构建和代理配置，明确开发端口 5173、默认后端 8080，以及通过环境变量更换代理目标的方法。生产发布需将 `/api` 反向代理至后端，并配置 SPA 路由回退，Vite preview 只用于查看构建结果。

后端采用 Spring Boot 4.1.1、Java 21、Spring Data JPA、Spring Session JDBC 和 MySQL 9.6。我配合整理数据库及 Session 表初始化、数据源、SSN_KEY、HTTPS Cookie 和财务参数要求，区分进程内 H2 合成演示与持久化运行环境。部署成果为配置示例和可复现步骤，本报告不宣称生产上线或正式验收已经完成。

## 五、协作方式与问题处理

我与李舒灿围绕接口字段、版本和状态讨论一致的处理方式，将后端规则转换为页面限制与可读提示。李兴旺、胡显赫负责测试和项目讨论，我为其提供请求契约、页面边界和复现入口，协助判断问题发生在交互、代理、接口或业务状态。张煜恒配合整理材料、核对页面与说明，支持阶段汇报准备。

工作中的主要困难是异步请求与业务状态可能同时变化。我通过恢复前确认账号、结果不明时重新查询和离页保护减少误操作；对于成绩版本和敏感字段，使用明确类型与空值语义，避免自行推断。外部集成则通过适配器与合成环境组织验证，保留真实依赖尚未确认的边界。
